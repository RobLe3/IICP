# MCP 2026-07-28 claim check — 2026-08-01

## Result

The claim that MCP `2026-07-28` is an authoritative, released protocol revision
is **not sufficiently supported by the current official TypeScript SDK package**.
This finding does not prove that the referenced web material is fabricated, but
it prevents IICP from treating that date as an established interoperability
target until the MCP project publishes consistent release evidence.

The npm package `@modelcontextprotocol/sdk@1.30.0`, inspected on 2026-08-01,
declares `2025-11-25` as `LATEST_PROTOCOL_VERSION`. Its supported-version list
is `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`, and `2024-10-07`.
The package also contains generated draft types labelled `DRAFT-2026-v1`, but
those are not part of the SDK's supported protocol-version list. The downloaded
package archive had SHA-256
`2cac3f3e38fec2815ed9efafa2947faf8c6957310684f99703f3d180f3e9af1a`.

## Local IICP evidence

The existing content-free IICP dual-era fixture remains useful as exploratory
design work. Current SDK tests passed without changing the public S.15 binding:

- Python: 10 MCP negotiation/gateway tests;
- TypeScript: 8 MCP negotiation/gateway tests;
- Rust: 2 MCP negotiation tests.

These results establish internal fixture parity only. They do not establish
interoperability with an official MCP `2026-07-28` implementation.

## Decision boundary

IICP issue 35 remains open for the released MCP `2025-11-25` authorization and
official-SDK interoperability matrix. The `2026-07-28` material stays
pre-normative and non-default. It must not be described as authoritative or
released unless the MCP specification, migration guidance, and an official SDK
converge on that version identifier.

No IICP wire behavior, SDK default, binding maturity label, release, or
deployment is authorized by this check.
