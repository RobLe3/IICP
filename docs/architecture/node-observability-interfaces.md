# Node observability interfaces for operator tooling

Status: **project architecture candidate for review**. This decision classifies
existing interfaces; it does not make every local log field part of the IICP
wire protocol or make a third-party monitor normative.

## Authority map

| Surface | Authority | Stability | Intended use |
|---|---|---|---|
| `GET /iicp/health` | Provider runtime interface defined by the IICP node contract | Stable required core fields; additive fields may vary by implementation/version | Direct liveness, capacity and effective service information from a node |
| `GET /v1/registry/stats` | Directory API | Versioned directory projection | Aggregate inventory without task payloads |
| `GET /v1/registry/intents` | Directory API | Versioned directory projection | Enumerate currently advertised Intent identifiers |
| `GET /v1/registry/nodes` | Directory API | Versioned, redacted directory projection | Enumerate public or caller-authorized provider inventory |
| Runtime-health snapshot | Local operational contract | Versioned by the producing runtime; not an IICP wire Profile | Supervised-process liveness/readiness and bounded reason codes |
| `events.jsonl` | Local operational contract | Versioned vocabulary below; not a directory or task protocol | Operator timeline and sidecar monitoring |
| Human-readable node log | Implementation detail | Unstable | Diagnosis by an operator; never parse as the primary machine interface |

Registry inventory answers what the authorized directory view contains.
Discovery answers which candidates are currently eligible for a particular
Intent and constraints. Monitoring software must not enumerate the registry by
repeatedly issuing selection queries when an authorized inventory API exists.

## Source and precedence

For runtime health, a monitor should use this order:

1. direct `GET /iicp/health` from the configured node;
2. a valid versioned runtime-health snapshot from that node's configured state
   location;
3. local event or log freshness as an explicitly labelled inference.

Failure of a higher-authority source may justify a bounded fallback, but the
fallback must remain labelled `inferred`. Log modification time is not proof
that inference is healthy or that a provider is eligible for dispatch.

For mesh inventory, prefer the configured directory's registry APIs. A legacy
discovery fallback is allowed only when the registry surface is unavailable and
must be labelled as incomplete. Private and local-only configurations must not
fall back to the public Genesis directory.

## Local operational event envelope

A JSONL operational event has these common fields:

| Field | Meaning |
|---|---|
| `ts` | UTC observation timestamp generated by the node runtime |
| `event` | Lowercase event identifier |
| `node_id` | Node-local subject identifier; monitoring output must redact it when disclosure is not authorized |
| `details` | Bounded implementation text; not a stable field grammar and never a secret channel |

The current stable vocabulary justified for third-party parsing is:

| Event | Class | Meaning |
|---|---|---|
| `serve_start` | lifecycle | The local serving loop started. It does not prove backend readiness. |
| `register_ok` | control success | The configured directory accepted registration. |
| `register_fail` | control failure | Registration failed. `register_error` may be recognized as a legacy alias but is not canonical. |
| `reregister_ok` | control success | A later registration or route update succeeded. |
| `reregister_fail` | control failure | A later registration or route update failed. |
| `heartbeat_ok` | control success | One heartbeat submission succeeded. |
| `heartbeat_fail` | control failure | One heartbeat submission failed. |
| `deregister_ok` | control success | Deregistration succeeded. |
| `deregister_fail` | control failure | Deregistration failed. |

An unknown event is `unknown`, not success. Consumers must preserve the raw
event name for diagnosis, render it neutrally and avoid changing health state
unless a later contract assigns semantics to it.

The envelope does not carry task prompts, results, credentials, complete routes,
membership assertions or private topology. Producers must not place those values
in `details`.

## Task observations

A change in a directory counter is an observation made when the counter was
read. It is not an original node event and does not establish the exact task
time. A monitor may represent it as `directory_task_delta` with an observation
timestamp, delta and directory-reported source. It must not manufacture
`task_ok`, `task_fail` or a provider timestamp from that delta.

If a future runtime exposes privacy-safe task lifecycle events, they require a
separate versioned extension with content exclusion, authorization and retention
rules. This document does not create those events.

## Configuration and privacy

Monitoring configuration follows the node's effective directory and log/state
locations. It may obtain values from explicit monitor configuration or a
redacted runtime configuration projection. It must not read bearer tokens,
private keys or operator secrets merely to infer whether security is configured.

Displayed facts must retain their provenance: `measured`, `configured`,
`directory_reported`, `locally_observed`, `inferred`, `legacy_fallback` or
`unavailable`. Deployment-specific claims such as tunnel use, IP masking, model
licensing or accepted tool classes are unavailable unless an authoritative
source supplies them.

Externally controlled strings are untrusted UI input. Web monitors must escape
or assign them as text, remain loopback-bound by default and require an explicit
operator decision before listening on a non-loopback address.

## Compatibility rules

- Additional health or registry fields are ignored unless understood.
- An unavailable optional source does not make the node healthy or unhealthy by
  itself; it changes the evidence state to unavailable or inferred.
- Unknown events remain neutral.
- Required private/local configuration that cannot be resolved fails before any
  public-directory request.
- Older event aliases may be accepted for display, but canonical output uses the
  vocabulary above.
- This contract does not require a monitor to be installed and does not place a
  monitor in the execution path.

The fixture in
[`node-observability-v1.json`](node-observability-v1.json) records current,
legacy and unknown event classifications plus the no-public-fallback rule.
